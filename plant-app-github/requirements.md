# 요구사항 정리 (MVP)

기준 문서: overview.md(규칙), plants.md, symptoms.md, solutions.md(내용), ui-text.md(화면 문구), design-system.md(모양). 와이어프레임 11장(wireframes.png)과 함께 본다.
이 문서는 "화면마다 무엇을 보여주고 어떻게 움직이는지"만 적는다. 문구·색·크기는 위 문서를 따른다.

## 범위
- 식물 5종: 로즈마리, 올리브나무, 스킨답서스, 스파티필럼, 몬스테라 (plants.md에 있는 식물만)
- 증상 3가지: 잎이 노래요 / 잎이 시들시들 처져요 / 잎 끝이 갈색이에요 (+ 여기에 없어요)
- 상태 2단계: 괜찮아요 / 도움이 필요해요
- 모바일 우선 웹, 로그인 없음, 데이터는 브라우저에 저장

## 데이터
- 내 식물: { 종류, 별명, 햇빛 정도(밝아요/보통/어두워요), 상태(없음/괜찮아요/도움이 필요해요), 마지막으로 본 해결책 번호 }
- 최대 9개(홈 칸 9개). 삭제는 가능, 수정은 없음.
- 읽기 전용 내용: plants.md, symptoms.md, solutions.md, ui-text.md. 코드에 문구를 직접 쓰지 않고 이 파일에서 읽는다.

## 화면별 요구사항
### 1. 홈 (내 식물)
- 제목은 "내 식물".
- 선반 3줄 × 칸 3개. 식물이 있는 칸: 화분 + 일러스트 + 별명 + 종류 + 상태 표시(있을 때만).
- 빈 칸: 화분 + 더하기 버튼 → 식물 등록으로 이동.
- 식물을 누르면 증상 고르기로 이동. 이미 해결책을 본 식물도 같다(다시 증상을 고른다).
- 오른쪽 위 톱니바퀴 아이콘을 누르면 편집 화면이 열린다(아래 "홈 편집").
- 식물 9개가 차면 더하기 버튼은 없다.
- 별명은 최대 15자. 홈 선반과 편집 화면처럼 칸이 좁은 곳에서만 5글자가 넘으면 앞 5글자 + "…"로 줄인다. 화면 제목(증상 고르기, 질문, 삭제 확인)과 식물 카드에서는 줄이지 않고 전체를 보여준다(제목이 길면 두 줄로 내려간다).

### 1-1. 홈 편집
- 제목 "편집", 안내 "식물을 끌어서 자리를 바꿀 수 있어요". 식물이 있는 칸마다 화분 왼쪽 위에 빼기 버튼이 보인다.
- 식물을 끌어서 다른 칸(빈 칸 포함)으로 옮기면 자리가 바뀌고, 바뀐 자리는 저장된다.
- 빼기 버튼을 누르면 삭제 확인 화면("{별명}을(를) 삭제할까요?" / 취소·삭제. 조사는 받침에 맞춰 하나만)으로 간다. 삭제하면 되돌릴 수 없다.
- 편집 중에는 더하기 버튼이 없고, 식물을 눌러도 증상 고르기로 가지 않는다. 아래 "완료" 버튼을 누르면 홈으로 돌아간다.

### 2. 식물 등록 (3단계)
1. 종류 검색: (홈으로 돌아가는 버튼은 없다. 와이어프레임 기준 [확정]) 입력한 글자가 plants.md의 식물 이름 어디에든 포함되면 결과에 나온다. 하나를 고르면 다음 버튼이 켜진다. 결과가 없으면 "찾는 식물이 아직 없어요"와 등록 가능한 식물 이름을 보여준다.
2. 별명: 글자를 입력해야 다음 버튼이 켜진다. 최대 15자까지 입력할 수 있다(15자를 넘으면 더 입력되지 않는다).
3. 햇빛 정도: 밝아요 / 보통 / 어두워요 중 하나. 하나를 골라야 "등록하기"가 켜진다 [확정]. "등록하기"를 누르면 저장하고 홈으로 돌아간다.
- 각 단계에서 이전 버튼으로 돌아가도 입력한 값이 남는다.

### 3. 증상 고르기
- 제목에 별명을 넣는다. 증상 3가지 + 맨 아래 "여기에 없어요". **하나만** 고를 수 있다(다른 것을 누르면 앞의 선택은 풀린다. 고른 것을 다시 누르면 선택이 풀린다).
- 아무것도 고르지 않고 다음을 누르면 상태를 "괜찮아요"로 저장하고 홈으로 돌아간다. (질문·해결책 화면으로 가지 않는다.)
- "여기에 없어요"를 고르면 다음 버튼은 막다른 화면으로 이동하고, 상태는 "괜찮아요"로 저장한다(11/20 결정).
- 단계는 symptoms.md가 정한다.

### 4. 질문
- symptoms.md의 질문 흐름대로 한 번에 한 질문. 질문마다 선택지 하나를 고르고 다음 질문으로 간다.
- 이전 질문 버튼으로 돌아갈 수 있다. 첫 질문의 이전 질문은 증상 고르기 화면으로 돌아가고, 고른 증상은 남는다.
- 질문 제목에 별명을 전체로 넣는다(줄이지 않는다. 예: "폴폴이의 흙 상태는 어떤가요?").
- 최근 변화 질문은 symptoms.md가 정한 조건일 때만 나온다.

### 5. 해결책
- "지금 모습 → 이유 → 해야 할 일" 순서. 식물 카드(일러스트, 별명, 종류, 상태 표시)가 위에 있다.
- 식물별 안내가 있으면 등록한 식물의 것만 "해야 할 일" 아래에 이어서 보여준다.
- [초안] 해결책이면 "확실하지 않아요"를 함께 보여준다. 식물 이름(등록 목록, 홈, 식물 카드)에는 붙이지 않는다.
- 뒤로 가기 → 홈. 상태는 식물에 저장해서 홈에 표시한다.

### 6. 막다른 화면
- 조건: "여기에 없어요"를 골랐을 때, 또는 고른 증상·답에 맞는 해결책이 solutions.md에 없을 때(예: 로즈마리 + 잎이 노래요 + 맨 아래 한두 장).
- "이 증상은 아직 안내를 준비하지 못했어요" + 처음으로 돌아가기(홈). 해결책이 없는 조합이면 새 상태는 저장하지 않고, 지난 상태도 지워서 홈의 상태 자리를 비운다(design-system.md "상태 표시"). "여기에 없어요"를 골라서 왔으면 상태를 "괜찮아요"로 저장한다.

## 규칙 (모든 화면)
- 화면에 보이는 글은 쉬운 말. 숫자를 새로 만들지 않는다. 모르면 추측하지 말고 묻는다.
- 색만으로 상태를 구분하지 않는다(점 + 글자).
- 한글은 단어 단위로 줄바꿈(word-break: keep-all).
- 만들지 않는 것: 사진 진단, AI 답변, 로그인·회원가입·알림, 식물 정보 수정(별명·종류·햇빛 정도. 자리 이동은 편집 화면에서 가능), 줄기·흙·뿌리 증상.

## 아직 비어 있는 것 (구축 전에 정하기)
- 식물을 다시 눌렀을 때 지난 상태를 보여줄지 여부(지금은 증상을 새로 고른다)

## 구축 순서 (한 번에 한 기능)
1. 홈 + 식물 등록(검색 포함) → 2. 증상 고르기 + 질문 → 3. 상태 + 해결책 + 막다른 화면 → 4. 디자인 다듬기
각 단계가 끝나면 고칠 점을 md에 먼저 적고 코드에 다시 반영한다.
