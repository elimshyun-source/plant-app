# 구축 시작 가이드 (사람용, 에이전트에게 읽히지 않아도 됩니다)

## 시작하기 (터미널 없이, Claude 데스크톱 앱으로)
1. Claude 데스크톱 앱을 설치하고 로그인한다. (Mac 또는 Windows. 유료 플랜이 필요하다.)
2. 이 zip의 압축을 풀어 `plant-app` 폴더를 컴퓨터 어딘가에 둔다. (예: 문서 폴더)
3. 앱 위쪽 가운데의 **Code** 탭을 누른다.
4. 환경은 **Local**을 고르고, **Select folder**로 `plant-app` 폴더를 선택한다. (CLAUDE.md는 자동으로 읽힌다.)
5. 아래 "지시문"의 **0번**을 입력창에 붙여 넣고 보낸다. Claude가 구성을 제안하면 읽어 보고 "좋아, 진행해줘"라고 답한다.
6. 그다음부터 1번, 2번, 3번 순서로 하나씩 붙여 넣는다. 한 단계가 끝나면 직접 눌러 보고 확인한 뒤에 다음으로 넘어간다.
- 화면이 만들어지면 앱 안의 브라우저 창에서 바로 미리 볼 수 있다.
- 어긋난 곳은 코드를 바로 고치게 하지 말고, md에 먼저 적고 "md 바꿨어, 다시 반영해줘"라고 한다.
- 파일을 고치기 전에 승인을 묻는 모드(Manual)로 시작하면, 무엇이 바뀌는지 보면서 진행할 수 있다.

## 지시문
### 0. 구성 정하기
CLAUDE.md, requirements.md, design-system.md를 읽고, 어떤 구성으로 만들지 제안해줘. 아직 코드는 쓰지 마.

### 1. 홈과 식물 등록
requirements.md의 홈, 홈 편집, 식물 등록(검색 포함)만 만들어줘. design-system.md의 값을 그대로 쓰고, 식물 일러스트는 assets/plants/를 써줘. 증상·해결책은 아직 만들지 마. 끝나면 확인 방법을 알려줘.

### 2. 증상 고르기와 질문
requirements.md의 증상 고르기와 질문을 만들어줘. 질문 흐름과 단계는 symptoms.md를 따라줘. 해결책 화면은 아직 만들지 마.

### 3. 해결책과 막다른 화면
requirements.md의 해결책과 막다른 화면을 만들어줘. 내용은 solutions.md에서만 가져오고, 해결책이 없는 조합은 막다른 화면으로 보내줘. 상태 표시를 홈과 식물 카드에 연결해줘.

### 4. 점검
모든 화면을 requirements.md와 design-system.md와 비교해서, 다른 곳을 목록으로 알려줘. 고치지는 말고 목록만.

## 확인할 때 보는 것 (단계마다)
- design-system.md의 숫자와 같은가: 여백 24, 모서리 16, 버튼 높이 58, 색
- 별명이 길 때(15자) 홈은 5글자 + …, 제목은 전체로 보이는가
- 해결책 문구가 solutions.md와 한 글자도 다르지 않은가
- md에 없는 기능이나 문구가 생기지 않았는가
